# PostService_WebApp_demo
Навчальний демонстраційний проєкт: простий вебсайт зі списком поштових відправлень і формою створення нового відправлення. Сторінки не містять готових даних: вони формуються динамічно в браузері за даними, які надсилає REST API сервіс `PostService` (проєкт `PostServiceSolution`).

> Зразок не є повною реалізацією і потребує доробок. Усе, що в ньому реалізовано, працює коректно, але деякі можливості (наприклад, редагування наявного відправлення) свідомо відсутні. Перелік можливих доробок наведено в кінці.

## Що демонструє проєкт

- **Динамічні сторінки.** Таблиця відправлень будується в JavaScript: створюються елементи `tr`, `td`, `button`, які додаються в DOM. Колонки визначаються атрибутами `x-column` у заголовку таблиці, тому додати колонку можна змінивши лише HTML.
- **Взаємодія з REST API.** Клас `PostingService` інкапсулює запити `fetch` (`GET`, `POST`, `DELETE`), перевірку коду відповіді та розбір помилок валідації, які повертає сервер (HTTP 400).
- **Робота з подіями.** Обробники `click` для кнопок видалення та відправлення форми, подія `input` для зняття помилки під час введення, подія `invalid` для показу власних повідомлень.
- **Робота з формами.** Валідація на боці клієнта через Constraint Validation API (`required`, `min`, `minlength`, `step`, `validity`, `setCustomValidity`), власні українські повідомлення про помилки, власне правило (максимальна вага для доставки до відділення), збирання даних через `FormData`.
- **Повідомлення користувачу.** Компонент `Toast` показує статус операції (успіх, попередження, помилка) і сам зникає за кілька секунд.

## Структура проєкту

| Файл | Призначення |
| --- | --- |
| `index.html` | Головна сторінка з навігацією |
| `about.html` | Сторінка «Про сайт» (заготовка) |
| `posting-list.html` | Список відправлень, кнопка «Створити», кнопки «Видалити» |
| `posting-edit.html` | Форма створення відправлення |
| `styles.css` | Спільні стилі всіх сторінок |
| `scripts/services/posting-service.js` | Робота з REST API, типи даних, перелік `DeliveryType`, клас `ServerValidationError` |
| `scripts/pages/posting-page.js` | Логіка сторінки списку: побудова таблиці, видалення |
| `scripts/pages/posting-edit-page.js` | Логіка сторінки форми: валідація, відправлення даних |
| `scripts/components/toast.js` | Компонент спливаючого повідомлення |
| `.vscode/` | Налаштування запуску вебсервера та браузера у VS Code |

Скрипти підключаються звичайними тегами `script` без модулів. Порядок підключення важливий: спочатку компонент і сервіс, потім скрипт сторінки.

## Запуск

Для роботи потрібні два процеси: REST API сервіс і статичний вебсервер для сторінок.

1. **Запустіть сервіс `PostService`** з рішення `PostServiceSolution` і подивіться в консолі, на якій адресі він слухає (рядок `Now listening on: http://localhost:...`). Порт залежить від налаштувань запуску: у `launchSettings.json` проєкту вказано `5211`, але на вашому комп'ютері він може бути іншим, наприклад `5000`. Клієнт за замовчуванням звертається до `http://localhost:5211`, тому якщо порт інший, змініть адресу в конструкторі `PostingService` (параметр `baseUrl` у файлі `scripts/services/posting-service.js`).
2. **Запустіть вебсервер для сторінок на порту 3000.** Варіанти:
   - у VS Code оберіть конфігурацію запуску «HTML/JS: Chrome (3000)» або «HTML/JS: Edge (3000)» (потрібен встановлений Node.js, сервер `http-server` завантажується автоматично);
   - або в папці проєкту виконайте команду `npx http-server . -a localhost -p 3000 -c-1`.
3. Відкрийте в браузері `http://localhost:3000`.
